## ۰) رانفلر چیست و چرا این پروژه روی آن خوب اجرا می‌شود؟

**رانفلر** (runflare.com) سکوی ابری شرکت پارس وب سرور است: استانداردهای Docker و
Kubernetes، پنل فارسی، دامنهٔ موقت رایگان و **پلن رایگان ۳ ماهه** (۳GB RAM / 1.5GHz
CPU / 3GB دیسک / ۲ deployment / کلاستر ایران — غیر production و بدون بکاپ).

بک‌اند SaliSurf-X از قبل برای این سکو آماده شده است:

| آمادگی | توضیح |
| --- | --- |
| `backend/Dockerfile` | ایمیج کامل با uvicorn، کاربر غیر root و healthcheck |
| `$PORT` | کانتینر به پورت تزریقی پنل گوش می‌دهد (`--port ${PORT}`، پیش‌فرض 8000) |
| `requirements.txt` | نقطهٔ ورود PaaS — همان lock پین‌شده را نصب می‌کند |
| `GET /api/v1/ready` | بررسی آمادگی (بنویسندگی artifacts را هم چک می‌کند) |

به بک‌اند هیچ کلید API یا دیتابیسی لازم نیست — Copernicus و DEM آزاد، ناشناس و
بدون حساب کاربری هستند.

## ۱) مسیر A — استقرار با CLI (پیشنهادی برای این ریپو)

چون `Dockerfile` در زیرپوشهٔ `backend/` است، ساده‌ترین راه آپلودِ همان پوشه با CLI است.

### ۱.۱ نصب CLI

در ترموکس (Termux) یا لینوکس/مک:

```bash
/bin/bash -c "$(curl -fsSL https://get.runflare.com/install.sh)"
```

نصب را با `runflare --version` تست کنید (اگر دستور شناخته نشد، ترمینال را یک‌بار
ببندید و باز کنید). برای به‌روزرسانی: `runflare update`.

### ۱.۲ ساخت پروژه و سرویس Docker در پنل (یک‌بار)

1. در runflare.com وارد شوید → **«ایجاد پروژه»** → یک ID انتخاب کنید → **«گام بعدی»**.
2. کلاستر/لوکیشن را انتخاب کنید → **«گام بعدی»**.
3. پلن منابع (پلن رایگان برای شروع کافی است) → **«ثبت نهایی»**.
4. وارد پروژه شوید → بخش **«سرویس ها»** → **«ایجاد»** → آیکون **Docker**.
5. تنظیمات سرویس Docker را پر کنید:
   - **پورت: 8000** (کانتینر به `$PORT`/8000 گوش می‌دهد)
   - منابع: حداقل 512MB RAM برای شروع
6. **«ایجاد»** را بزنید.

### ۱.۳ آپلود کد بک‌اند

```bash
# در روت پروژه (پوشه‌ای که از ZIP استخراج کردید) اگر backend/ زیرپوشه است:
cd ~/SaliSurf-X-src/backend     # یا هر جایی که Dockerfile است
runflare deploy
```

- بار اول: پروژه و سرویس را با کلیدهای جهت‌دار انتخاب کنید.
- دفعات بعد: `runflare deploy -y` مستقیم به همان سرویس می‌رود.
- CLI فقط فایل‌های تغییر یافته را می‌فرستد و `.gitignore` را رعایت می‌کند.
- اگر مسیر deploy را عوض کردید: `runflare reset` مسیر را پاک می‌کند تا دوباره انتخاب کنید.
- بعد از آپلود، پنل/CLI لاگ زندهٔ build و اجرا را نشان می‌دهد — باید
  `Uvicorn running on http://0.0.0.0:8000` را ببینید.

## ۲) مسیر B — استقرار خودکار از GitHub (CI/CD)

هر push به شاخهٔ `main` بک‌اند را دوباره deploy می‌کند.

### ۲.۱ اتصال GitHub (روش OAuth — پیشنهادی)

1. در پنل رانفلر: **مدیریت پروژه** → پروژه‌تان → تنظیمات سرویس Docker →
   **«اتصال به مخزن گیت»**.
2. **«گیت هاب oAuth app»** را انتخاب کنید → **«افزودن حساب»**.
3. در صفحهٔ GitHub روی **«Authorize runflare cloud»** بزنید و ریپوی
   `SaliSalvia/SaliSurfX` را (یا همهٔ ریپوها را) مجاز کنید.
4. برگردید و **«اتصال»** را بزنید → ریپو و شاخهٔ `main` را انتخاب کنید → **«ذخیره»**.
5. در لیست commitها روی **«revert»** کنار کامیتی که می‌خواهید مستقر شود بزنید.
6. گزینهٔ **«دریافت خودکار»** را فعال کنید تا هر push، خودکار redeploy شود.

> **نکتهٔ مسیر:** رانفلر `Dockerfile` را باید در مسیر deploy پروژه پیدا کند.
> اگر پنل مسیر/Root Directory دارد، آن را روی **`backend/`** بگذارید. اگر چنین
> گزینه‌ای در سرویس شما نیست، از **مسیر A (CLI)** استفاده کنید که مستقیم پوشهٔ
> `backend/` را آپلود می‌کند — همین دلیل مسیر A «پیشنهادی» است.

### ۲.۲ روش جایگزین: توکن کلاسیک

GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
→ Generate new token با دسترسی `repo` → سپس در رانفلر «گیت هاب کلاسیک» را انتخاب و
آدرس ریپو + شاخه + توکن را وارد کنید. (وقتی توکن منقضی شود دریافت خودکار می‌ایستد.)

## ۳) تنظیمات سرویس (خلاصه پنل)

| تنظیم | مقدار پیشنهادی |
| --- | --- |
| پورت (port) | `8000` — یا همان پورتی که پنل تزریق می‌کند (CMD به `$PORT` گوش می‌دهد) |
| Health check | `GET /api/v1/ready` (در Dockerfile تعبیه شده) |
| RAM | شروع: 512MB–1GB · پلن رایگان ۳GB · برای پردازش deep (پیکسل Sentinel-2) بیشتر |
| Secret/Env | لازم نیست — کل سرویس بدون کلید کار می‌کند |
| دیسک | برای ماندگاری خروجی‌های `/app/deep_jobs` یک «دیسک جدید» بسازید و mount کنید |

## ۴) دامنه و اتصال اپ اندروید

### ۴.۱ فعال‌سازی دامنهٔ موقت

در جزئیات سرویس → **«فعالسازی دامنهٔ موقت»** → آدرسی شبیه
`https://<نام>.<کلاستر>.runflare...` می‌گیرید. این همان نشانی عمومی بک‌اند است.

### ۴.۲ اتصال اپ SaliSurf-X

1. اپ SaliSurf-X را باز کنید → تب **Settings**.
2. در فیلد **Backend connection / API URL** بنویسید:
   `https://<دامنهٔ-موقت-شما>/` (حتماً با `/` پایان یابد).
3. **Save** و بعد **Test connection** — باید «Online» و نسخهٔ بک‌اند (مثلاً `1.3.0`)
   نمایش داده شود.

بعد از این: روی تب **Map** ناحیه بکشید، Lock کنید، «Collect data» بزنید —
کاتالوگ Sentinel-2 و شاخص‌های terrain از بک‌اند رانفلر می‌آیند.

> اپ فقط برای URLهای `http://` LAN محلی اجازهٔ cleartext می‌دهد؛ آدرس `https://`
> رانفلر بدون هیچ تنظیم امنیتی اضافه‌ای کار می‌کند.

## ۵) تست سلامت پس از استقرار

```bash
BASE="https://<دامنهٔ-موقت-شما>"

curl "$BASE/api/v1/health"    # {"status":"ok","version":"1.3.0",...}
curl "$BASE/api/v1/ready"     # {"status":"ready",...,"artifacts_dir":true}
```

- `GET /docs` — Swagger UI (همهٔ endpointها)
- `GET /deep-console` — کنسول پردازش عمیق در مرورگر
- `POST /api/v1/regions/validate` — اعتبارسنجی چندضلعی (بدون تماس خارجی)
- `POST /api/v1/regions/catalog-search` — کاتالوگ واقعی Sentinel-2 (Copernicus)
- `POST /api/v1/regions/terrain-indicators` — شاخص‌های DEM واقعی (AWS Terrarium)

نمونهٔ تست سریع (تهران — در محیط تست ما همین فراخوانی‌ها پاسخ واقعی برگرداند):

```bash
curl -X POST "$BASE/api/v1/regions/validate" \
  -H "Content-Type: application/json" \
  -d '{"polygon":[[51.38,35.69],[51.42,35.69],[51.42,35.72],[51.38,35.72]]}'
```

## ۶) نکات عملیاتی

- **پلن رایگان** برای دمو/توسعه عالی است (۳ ماه، کلاستر ایران، بدون بکاپ).
  بعد از آن یا تمدید کنید یا به پلن ساعت‌ای/ماهانه بروید.
- **لوکیشن ایران:** تماس‌ها به Copernicus (اروپا) ممکن است کمی کند باشند
  (در تست ما ~۱۰ ثانیه برای catalog-search) — عادی است.
- **ماندگاری:** `/app/deep_jobs` (خروجی GeoTIFF/PNG پردازش عمیق) روی دیسک
  ایمیج است؛ با rebuild از بین می‌رود. برای نگهداری، «ساخت دیسک جدید» در پنل
  و mount آن روی این مسیر.
- **به‌روزرسانی زنجیره‌ای:** push به `main` → GitHub Actions APK می‌سازد و
  release می‌کند؛ اگر «دریافت خودکار» رانفلر فعال باشد، بک‌اند هم خودکار
  redeploy می‌شود. کل سیستم با یک push به‌روز می‌شود.
- **بیلد محلی ایمیج** (برای اشکال‌زدایی Dockerfile):
  `cd backend && docker build -t salisurfx-api . && docker run -p 8000:8000 salisurfx-api`

## ۷) اشکال‌زدایی سریع

| نشانه | علت رایج | راه‌حل |
| --- | --- | --- |
| در لاگ: `ModuleNotFoundError` | مسیر deploy روتِ ریپو است نه `backend/` | مسیر A یا Root Directory=`backend/` |
| در لاگ: پورت در use / Connection refused | پورت پنل ≠ پورت گوش‌دادن | پنل 8000؛ CMD به `$PORT` گوش می‌دهد — مطمئن شوید env درست تزریق شده |
| `/api/v1/ready` 503/404 | کانتینر هنوز بالا نیامده | چند لحظه صبر؛ لاگ build/اجرای سرویس را ببینید |
| catalog-search timeout | کندی مسیر IR→EU | دوباره تلاش کنید؛ پنجرهٔ تاریخ کوچک‌تر بگیرید |
| اپ «Offline» می‌ماند | URL بدون `/` پایانی | Settings → URL با `/` تمام شود → Save → Test |
